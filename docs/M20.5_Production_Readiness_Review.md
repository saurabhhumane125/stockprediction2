## 3. End-to-End Flow

1. **User Opens App**: Navigates to the Dashboard or Stocks page.
2. **Select Stock**: Chooses a stock (e.g., RELIANCE).
3. **Submit Prediction**: Triggers the live prediction workflow.
4. **Backend Request**: Hits `POST /predict/live/{stock}`.
5. **Data Gathering**: Backend fetches live OHLCV data, calculates sequences, and pulls recent news.
6. **Inference**: Backend delegates to `prediction_service`, which proxies the request to the `InferenceEngine` via the `ml_adapter`.
7. **Response Generation**: The prediction (BUY/SELL), confidence, explanation, and market regime are packaged.
8. **Frontend Rendering**: UI updates with the results.

*Future ML model improvements (like Experiment #1) plug directly into Step 6 without requiring any UI or API contract changes.*

## 4. ML Integration

- **Current Inference Path**: The `PredictionService` first attempts to route the request through `ml_adapter.inference_engine`. If successful, the new framework handles prediction. It contains a seamless legacy fallback.
- **Active Model Loading**: Models and features are dynamically loaded during the FastAPI `lifespan` via `artifacts.load_artifacts()`.
- **Registry & Decoder**: The `InferenceEngine` loads the active configuration from the model registry, applies the corresponding Target Strategy, and selects the proper decoder.
- **Experiment 1 Compatibility**: Because the `VolatilityAdjustedReturnStrategy` and its corresponding decoder adhere to the core Registry and InferenceEngine contracts, Experiment 1 introduces **no breaking changes** to the inference pipeline. The API schemas remain perfectly intact.
